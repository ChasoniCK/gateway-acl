# Управление VPN-туннелями из панели

Дата: 2026-08-27. Статус: согласовано в чате и проверено исполнителем; пользователь
поручил перейти к плану без отдельной ручной проверки документа.

## Цель

Добавить в существующий шит «Настройки» управление VPN-профилями без отдельной
админки и без произвольного доступа к systemd:

- несколько ссылок подписок, объединяемых в один sing-box;
- обычные конфиги WireGuard;
- конфиги AmneziaWG;
- добавление, обновление, включение, выключение и удаление из браузера;
- атомарное переключение с возвратом предыдущего рабочего туннеля при ошибке.

Под «сервисом» здесь понимается только один из трёх поддержанных VPN-бэкендов.
Панель не становится универсальным редактором systemd-служб и не принимает имена
команд или unit-файлов от браузера.

## Не входит в работу

- установка `sing-box`, `wg-quick`, `awg-quick`, kernel-модулей или репозиториев
  пакетов из браузера;
- произвольные shell hooks из WG/AWG-конфига;
- одновременная работа двух default-route туннелей;
- вывод существующего URL, приватного ключа или полного конфига обратно в UI;
- TLS для панели. Панель сохраняет существующую модель доверенной локальной сети;
  вводимые секреты по HTTP не защищены от перехвата внутри LAN;
- постоянный kernel-enforced kill-switch до старта systemd и между опросами панели.
  Эта работа закрывает утечку внутри управляемой операции переключения, но не обещает
  переживающее остановку gateway-acl правило ранней загрузки;
- изменение, отключение или переподключение сети/VPN на macOS-ноутбуке во время
  интеграционных тестов.

## Пользовательская модель

В шите «Настройки», после группы «Сеть», появляется группа «Туннели».

Каждая строка показывает:

- имя;
- тип: подписка, WireGuard или AmneziaWG;
- текстовое состояние: выключен, подключён, ошибка или отсутствует нужный инструмент;
- действия «Включить/Выключить», для подписки также «Обновить», и «Удалить».

Цвет может дублировать состояние, но не заменяет текст. Результат операции
объявляется через `aria-live=polite`.

Форма добавления использует существующие HTML-примитивы панели:

- имя до 40 символов;
- выбор «Подписка», «WireGuard» или «AmneziaWG»;
- для подписки — HTTPS URL и необязательное регулярное выражение исключения узлов;
- для конфига — `<textarea autocomplete="off" spellcheck="false">`.

Тип WG/AWG задаётся явно: это не даёт новой версии AmneziaWG с дополнительными
параметрами ошибочно пройти как обычный WireGuard. Сервер всё равно отклоняет явное
несоответствие выбранного типа и конфига. Новый профиль сохраняется выключенным.
Секретные поля очищаются после ответа сервера и никогда не заполняются существующим
значением.

Несколько подписок могут быть включены одновременно: их узлы входят в одну группу
sing-box `proxy`. Включение WG/AWG выключает все подписки; включение подписки
выключает активный WG/AWG. Одновременно допустимо ровно одно состояние:

1. туннеля нет;
2. sing-box с одной или несколькими подписками;
3. один профиль WireGuard или AmneziaWG.

Явное выключение последнего туннеля возвращает шлюз к обычной маршрутизации без VPN.
Перед этим UI предупреждает, что разрешённые устройства пойдут напрямую.

## Хранение

Метаданные лежат в `/etc/gateway-acl/tunnels.json`. Файл не содержит URL,
subscription body или WG/AWG-конфигов. Запись каталога имеет поля:

```json
{
  "id": "t0123456789ab",
  "name": "Frankfurt",
  "kind": "subscription",
  "enabled": false,
  "error": "",
  "nodes": 0
}
```

`id` создаётся сервером из фиксированного префикса и случайных hex-символов,
проверяется строгим regex и не зависит от пользовательского имени.

Секреты лежат отдельно в каталоге `/etc/gateway-acl/tunnels/` с mode `0700`, только
в файлах, чьи имена
получены из проверенного `id`:

- `<id>.json` для URL, exclude и последнего успешно полученного тела подписки;
- `<id>.conf` для WG/AWG-конфига.

Каталог и секреты пишутся private-atomic операцией: временный файл `0600`,
`flush`, `fsync`, `os.replace`, затем `fsync` родительского каталога. URL, тела
подписок, ключи, endpoint и конфиги не
попадают в HTML, JSON-ответы, exception text, журнал или argv процесса.

Последнее успешно полученное тело подписки кэшируется. Поэтому выключение или
удаление одной подписки и пересборка оставшихся не зависят от доступности их серверов.
Сеть требуется только при добавлении и явном «Обновить».

Все изменения каталога и внешний lifecycle сериализуются одним lock. Изменение
`vpn_mark` и сохранение обычных настроек используют общий config lock, чтобы два
параллельных запроса не перезаписали изменения друг друга.

Несколько файлов не объявляются одной файловой транзакцией. Порядок записи всегда
`secret/cache → внешний конфиг → runtime → config.json → tunnels.json`; каталог
коммитится последним. На старте reconciliation удаляет только принадлежащие панели
orphan temporary files, помечает запись с отсутствующим secret выключенной с ошибкой
и заново выводит `vpn_mark` из фактически работающего управляемого backend.

## HTTP API и защита

Добавляется точный authenticated endpoint `/vpn`:

- `GET /vpn` — безопасный список профилей и capability/status;
- `POST /vpn` — одно из фиксированных действий `add`, `enable`, `disable`, `refresh`;
- `DELETE /vpn?id=<server-id>` — удалить принадлежащий панели профиль.

Неизвестные методы, пути и действия возвращают `404`/`400`, а не попадают в
обработчик устройств. Существующие `/api` и удаление устройств также переводятся
с prefix/fallback-маршрутизации на точные пути.

До чтения тела запроса, кроме ограниченного `/login`, выполняется авторизация.
Общий `Content-Length` ограничивается 128 КиБ; отрицательное, нечисловое или большее
значение, отсутствующая длина или `Transfer-Encoding` получает `400`/`411`/`413`.
Все изменяющие fetch-запросы передают CSRF-токен в `X-CSRF-Token`; он выводится из
сырого session cookie и случайного process secret, выдаётся только в authenticated
`/api`/`/vpn` и проверяется constant-time. После рестарта вкладка получает новый токен
при следующем `load()`. Logout становится CSRF-защищённым POST. Сессионная cookie
сохраняет `HttpOnly; SameSite=Strict`.

`GET /vpn` возвращает только:

- `id`, `name`, `kind`;
- `enabled`, фактический `active`;
- число узлов подписки;
- безопасное сообщение ошибки без stdout/stderr внешнего инструмента.

## Валидация подписок

- URL обязан иметь схему `https` и hostname; `file:`, `data:`, локальный путь и
  остальные схемы отклоняются до `urllib`. Cross-host redirect запрещён. URL является
  привилегированным вводом авторизованного администратора доверенной LAN; защита от
  DNS rebinding и обращения к внутреннему HTTPS-хосту в эту работу не входит.
- Ответ читается как `limit + 1`, чтобы превышение было ошибкой, а не тихим усечением;
  запрос имеет общий deadline.
- Регулярное выражение ограничено 128 символами и компилируется до записи. Это
  совместимость с существующим `sub.exclude`; URL и выражение считаются доверенным
  административным вводом.
- Подписка должна дать хотя бы один поддержанный узел.
- Ошибки конвертера преобразуются в обычные исключения уровня API, а не завершают
  root-процесс через `SystemExit`.

`singbox_sub.py` остаётся конвертером и импортируется как модуль, чтобы URL не был
виден в `ps`. Каждая подписка получает prefix `sub-<id>-`, а все конверсии используют
общий набор занятых тегов. Затем выполняется один `merge`, один `sing-box check` и
один restart; последовательный merge, который удалил бы предыдущую подписку,
запрещён архитектурой.

## Валидация WireGuard и AmneziaWG

Перед сохранением конфиг:

- должен быть UTF-8, не больше 128 КиБ и без NUL;
- должен содержать ровно один `[Interface]`, `PrivateKey`, `Address` и хотя бы один
  `[Peer]` с `PublicKey`, `AllowedIPs` и `Endpoint`;
- не должен содержать регистронезависимые `PreUp`, `PostUp`, `PreDown`, `PostDown`
  или `SaveConfig`;
- выбранный WireGuard отклоняет AWG-only параметры; выбранный AmneziaWG обязан иметь
  хотя бы один поддержанный установленной версией `awg` AWG-only параметр;
- если соответствующий quick-tool установлен, проходит `wg-quick strip` либо
  `awg-quick strip` до записи.

Отсутствие `wg-quick`/`awg-quick` не запускает установку: структурно корректный профиль
сохраняется со статусом «не проверен: tool отсутствует». Перед включением quick-tool
и успешный `strip` обязательны. Отсутствующий AmneziaWG module/userspace даёт понятную
capability-ошибку без изменения активного backend.

Управляемый профиль должен быть full-route клиентом: `AllowedIPs` включает
`0.0.0.0/0`; `Table = off` и произвольная таблица не поддерживаются. IPv6 `::/0`
необязателен, но его отсутствие явно показывается в статусе. Split-tunnel профили
нельзя пометить как активный VPN всего шлюза в этой версии.

Пользовательское имя никогда не входит в путь, interface name, команду или systemd
unit. Все процессы запускаются argv-массивом с фиксированным отображением kind →
tool, `shell=False` и timeout.

## Переключение и откат

Любое изменение активного состояния выполняется под lifecycle lock. Панель останавливает
только backend, записанный в её каталоге; обнаруженный посторонний default-route tunnel
считается конфликтом и не изменяется.

Включение выполняется так:

1. проверить новый профиль, tool и кандидат-конфиг;
2. для sing-box создать private temporary config и выполнить `sing-box check`;
3. временно закрыть транзитный трафик правилами gateway-acl, чтобы короткое окно
   между туннелями не выпустило устройства напрямую;
4. остановить старый backend;
5. запустить новый и проверить интерфейс, policy routes и правила, не ожидая handshake;
6. прочитать фактический fwmark с хоста;
7. только после успеха атомарно сохранить enabled-state и `vpn_mark`, затем
   перестроить `inet gwacl`;
8. при любой ошибке остановить candidate, восстановить конфиг и старый backend,
   вернуть старый mark и только затем снова открыть разрешённый транзит.

Для WG/AWG фактическое состояние проверяется по интерфейсу и установленным routes,
mark читается через `wg|awg show <interface> fwmark`; свежесть handshake показывается
отдельно и не откатывает успешный `up`. Для sing-box требуются успешный
`systemctl restart`, `systemctl is-active` и однозначный output mark из правил хоста.
Неоднозначный или отсутствующий mark означает `vpn_mark = 0`, а не значение из
документации.

Active refresh сначала получает и проверяет новый cache/config, затем применяет его;
cache и node count коммитятся только после успешного restart. Ошибка оставляет старые
cache, sing-box config и runtime. Disable/delete активной подписки сначала собирает
candidate из оставшихся enabled sources; удаление последней останавливает sing-box и
только после успеха удаляет secret/metadata. Disable/delete WG/AWG сначала выполняет
`quick down`; при ошибке запись и secret сохраняются для повторного восстановления.

Во время управляемого switch правила временно закрывают транзит, и это состояние
сохраняется до commit либо полного rollback. После явного выключения последнего
backend прямой маршрут разрешён. Внешнее падение backend обнаруживается status-check
не позднее следующего `POLL_SEC`, после чего панель закрывает управляемый транзит и
показывает ошибку; спецификация не обещает отсутствие утечки до обнаружения и до
старта gateway-acl после reboot.

На старте панель reconciles каталог и пытается восстановить сохранённый backend.
Ошибка туннеля не должна уронить HTTP-панель: пользователь обязан иметь возможность
открыть её, исправить профиль или явно выключить VPN.

## Миграция и установка

При первом запуске новой версии, если каталога ещё нет, существующие `sub.url` и
`sub.exclude` переносятся в secret профиля «Подписка» без раскрытия в UI. Профиль
получает состояние `legacy/no-cache`; текущий sing-box config и active service не
пересобираются до успешного «Обновить». После успешной private-atomic записи secret
legacy-файлы удаляются, чтобы удалённый в UI секрет не появился снова на следующем
старте.

`install.sh` после миграции больше не обновляет активную подписку на каждом обновлении
панели. Он по-прежнему копирует `singbox_sub.py`, проверяет собственный синтаксис и
не меняет рабочий маршрут при `--yes`.

Обновляются одновременно:

- `README.md` и `README.ru.md`;
- `docs/design.md` — состояния, kill-switch и fwmark;
- `docs/singbox.md` — несколько источников и новая граница владения.

`VERSION` повышается с `1.5.0` до `1.6.0`; release tag по-прежнему обязан совпасть.

## Автоматические проверки

Разработка идёт red-green в существующих `selftest()` без сети и root. Проверяются:

- private-atomic запись и mode `0600`;
- схема каталога, server-generated id и path traversal;
- отсутствие URL, subscription body и ключей в public state и ошибках;
- URL scheme, regex и размеры;
- запрет hooks/`SaveConfig`, соответствие выбранного WG/AWG типа и минимальная
  структура конфига;
- объединение двух подписок, уникальные tags, refresh и удаление одной без потери второй;
- ровно один активный backend;
- argv только из фиксированных tool names и безопасного пути;
- success и каждый rollback-переход через fake external runner с проверкой реального
  файлового/catalog state, а не самого mock;
- разбор fwmark и поведение при неоднозначном результате;
- закрытый транзит во время управляемого switch и прямой маршрут только после
  commit либо полного rollback;
- auth-before-body, 128-КиБ limit, CSRF и точная маршрутизация `/api`, `/vpn`, DELETE;
- DOM id, RU/EN parity и отсутствие секретов в отрендеренной странице;
- миграция `sub.url` выполняется один раз.

После каждого нового red-green блока запускаются затронутые selftest; перед сдачей —
полный набор команд из `AGENTS.md`, включая `nft -c` generated ruleset.

## Реальные интернет-тесты

Реальные тесты выполняются только после автоматических и только в изолированной
Linux-среде, где изменение default route не затрагивает macOS-хост:

- отдельная Linux VM, либо network namespace/контейнер с собственной routing table и
  нужными `NET_ADMIN`/AmneziaWG capabilities;
- запрещено останавливать, переподключать или менять VPN, Wi-Fi, Ethernet, utun и
  default route ноутбука;
- до и после тестов read-only проверяется, что хостовый default route и доступ в
  интернет сохранились;
- если подходящей изоляции, `awg-quick` или AmneziaWG implementation нет, тест
  помечается заблокированным окружением; вместо этого нельзя поднимать конфиг на хосте.

Разрешено использовать конфиг с приложенного изображения. Он считается секретом:

- извлекается только во временный файл `0600` вне репозитория;
- не выводится в terminal output, логи, ответы, diff или отчёт;
- после теста временный файл удаляется;
- поскольку ключи уже были показаны на изображении, после проверки рекомендуется
  перевыпустить профиль.

Один WireGuard/AWG peer может перемещаться на последний увиденный endpoint. Поэтому
присланный профиль нельзя поднимать параллельно, если он используется текущим VPN
ноутбука: это способно оборвать именно соединение, которое запрещено трогать. Без
read-only подтверждения, что профиль не активен, он используется только для parser/UI
проверок; live handshake требует отдельного disposable peer.

В изоляции проверяются:

1. `awg-quick strip` и запуск профиля;
2. handshake и рост transfer counters;
3. DNS, IPv4, а при наличии маршрута IPv6;
4. внешний HTTPS-запрос через AWG;
5. выключение и повторное включение;
6. неуспешный candidate и возврат предыдущего backend;
7. закрытие транзита при аварийной остановке активного backend;
8. отсутствие изменений маршрутов и VPN на macOS-хосте.

Тест подписок использует только явно предоставленную пользователем HTTPS-ссылку или
локальный controlled fixture; чужой публичный сервис и случайный URL не подбираются.

## Критерии готовности

- UI выполняет CRUD и lifecycle для подписок, WireGuard и AmneziaWG.
- Несколько подписок сосуществуют в одной группе sing-box и удаляются независимо.
- В один момент активен только один backend-класс.
- Любой failed switch восстанавливает предыдущий рабочий backend и mark.
- Секреты остаются `0600` и отсутствуют во всех browser-visible данных.
- Никакой конфиг не может выбрать command, path, unit или выполнить hook от root.
- Управляемое переключение не имеет намеренного direct-route окна; внешний crash
  обнаруживается и закрывается в пределах poll interval без обещания раннего boot
  kill-switch.
- Старая `sub.url` мигрирует без потери рабочего маршрута.
- Все автоматические проверки проходят; реальные проверки либо проходят в изоляции,
  либо честно отмечены как недоступные без изменения сети ноутбука.
